1. EXECUTIVE SUMMARY & REBRANDING STRATEGY
========================================================================================================================

The project "Email Summarizer (Win32)" (repository: `ismlEraslan/email-summarizer-win32`, WinGet package:
`ismlEraslan.EmailSummarizer`) is undergoing a complete, permanent rebranding to:

                       =============================================
                                     KERKENEZ MAIL
                       =============================================

This rebranding encompasses:
- Application Binary & Executable Name: `KerkenezMail.exe`
- Application Title & Branding: `Kerkenez Mail (Win32)` / `Kerkenez Mail`
- Roaming AppData Directory: `%APPDATA%\KerkenezMail`
- DPAPI Cryptographic Entropies: `KerkenezMail.SecureAccounts.v1` & `KerkenezMail.SecureSecrets.v1`
- Windows Registry Uninstall Key: `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\KerkenezMail`
- Windows Logon Startup Run Key: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\KerkenezMailTray`
- Windows Kernel Mutexes & Events: `Global\KerkenezMail_MainUI_Mutex`, `Global\KerkenezMail_TrayDaemon_Mutex`,
  `Global\KerkenezMail_TrayDaemon_ExitEvent`
- Windows Shell Shortcuts: `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Kerkenez Mail.lnk`,
  `%USERPROFILE%\Desktop\Kerkenez Mail.lnk`
- Windows Package Manager (WinGet): New package identifier `ismlEraslan.KerkenezMail`

THE TWO-STAGE TRANSITION STRATEGY:
Because existing users have installed the app via `winget install ismlEraslan.EmailSummarizer` or standalone zip downloads,
a direct abrupt change of package name would strand all existing users on the old version without update notifications.
Therefore, a strategic two-stage bridge transition is deployed:

STAGE 1: Release `v0.5.0-bridge` under the OLD WinGet Identifier (`ismlEraslan.EmailSummarizer`)
  - Target Version: `v0.5.0`
  - WinGet Package ID: `ismlEraslan.EmailSummarizer`
  - Role: The Heavy Transition Bridge. It embeds the comprehensive, fault-tolerant `MigrationService` that carries out
    the entire migration on the user's machine automatically upon first boot.
  - Core Operations in v0.5.0:
    1. Detects existing `%APPDATA%\EmailSummarizer` configuration and encrypted accounts.
    2. Initializes `%APPDATA%\KerkenezMail`.
    3. Decrypts all accounts from old `accounts.dat` using legacy DPAPI entropy and re-encrypts them into the new
       `%APPDATA%\KerkenezMail\accounts.dat` using new `KerkenezMail` DPAPI entropy.
    4. Decrypts and re-encrypts Cloud API Keys in `config.json`, migrates general preferences, and writes to
       `%APPDATA%\KerkenezMail\config.json`.
    5. Validates file integrity and test-decrypts the new files.
    6. Upon 100% verified success, completely cleans up and deletes `%APPDATA%\EmailSummarizer`.
    7. Updates Windows Registry Uninstall key to `KerkenezMail` and deletes old `EmailSummarizer` uninstall key.
    8. Updates Windows Startup Run key to `KerkenezMailTray` and removes old `EmailSummarizerTray` key.
    9. Creates `Kerkenez Mail.lnk` shortcuts on Desktop/Start Menu and deletes old `Email Summarizer.lnk` shortcuts.
    10. Displays a persistent, informative Rebranding Modal & Banner at startup informing users of the rebranding and
        providing one-click instructions to switch their WinGet package to `ismlEraslan.KerkenezMail`.

STAGE 2: Official Launch of `Kerkenez Mail v1.0.0`
  - Target Version: `v1.0.0`
  - WinGet Package ID: `ismlEraslan.KerkenezMail`
  - Repository / Project: `KerkenezMail.csproj` -> `KerkenezMail.exe`
  - Role: The clean, permanent product release.
  - Safeguard: Contains an autonomous background migration check that runs silently on startup so that if any user
    jumps directly from an old version (v0.1 - v0.4.1) directly to v1.0.0 without going through v0.5.0-bridge, their
    data and registry entries are still 100% safely migrated to `KerkenezMail`.

2. COMPLETE CODEBASE FEATURE & ARCHITECTURAL INVENTORY
========================================================================================================================

The current application is a high-performance, native Win32/Windows Forms desktop application built on .NET 8.0-windows,
engineered for multi-account email retrieval, executive summary generation, and priority triage via local/cloud AI.

2.1. Core Application & Lifecycle Architecture
----------------------------------------------
- `Program.cs`: Entry point containing CLI argument parsing and mode switching:
  * `--uninstall` / `-uninstall` / `/uninstall` (with `--quiet` / `--silent` / `-s` / `-q`): Executes `HandleUninstall`,
    calling `ConfigService.Uninstall()` to remove shortcuts, startup keys, uninstall registry entries, and `%APPDATA%`.
  * `UninstallRegistrationService.RegisterOrUpdate()`: Self-registers application in `HKCU\...\Uninstall` and synchronizes
    startup path if binary was relocated.
  * `--daemon` / `--tray`: Enters headless Win32 system tray background daemon mode (`NativeTrayDaemon.Run()`), protected
    by single-instance mutex `Global\EmailSummarizer_TrayDaemon_Mutex`.
  * Normal GUI Mode: Acquires `Global\EmailSummarizer_MainUI_Mutex`. If another GUI instance is active, invokes
    `NativeMethods.FocusMainWindow()` and exits. Launches `MainForm` with auto-start of daemon if `AlwaysKeepOn` is true.

2.2. Data Persistence & DPAPI Cryptography Layer
------------------------------------------------
- `ConfigService.cs`:
  * `AppDataFolder`: Points to `%APPDATA%\EmailSummarizer`.
  * `ConfigFilePath`: `%APPDATA%\EmailSummarizer\config.json`.
  * `AccountsFilePath`: `%APPDATA%\EmailSummarizer\accounts.dat`.
  * `LoadConfig()` / `SaveConfig()`: JSON serializer for `AppSettings`. Includes backward-compatibility migration for
    legacy plain-text accounts and plain-text API keys.
  * `GetAccounts()` / `SaveAccounts()`: Interacts with `AccountCryptoService`.
  * `Uninstall()`: Removes Windows Run key `EmailSummarizerTray`, unregisters from Uninstall registry, deletes shortcuts,
    and wipes `%APPDATA%\EmailSummarizer`.
- `AccountCryptoService.cs`:
  * Windows DPAPI encryption (`ProtectedData.Protect` / `ProtectedData.Unprotect`) with `DataProtectionScope.CurrentUser`.
  * `Entropy`: `Encoding.UTF8.GetBytes("EmailSummarizer.SecureAccounts.v1")` for binary account payload.
  * `StringEntropy`: `Encoding.UTF8.GetBytes("EmailSummarizer.SecureSecrets.v1")` for Base64-encrypted Cloud API keys.
  * Atomic file writes using temporary file swap (`.tmp` -> rename).
- `AppSettings.cs`:
  * Strongly typed configuration model containing AI backend selection (`LlamaCpp`, `Ollama`, `Cloud`), llama.cpp server
    settings, Ollama parameters, encrypted `CloudApiKeyEncrypted` with in-memory `CloudApiKey`, global temperature,
    token limits, context limits (`MaxSummaryEmailChars`), window scaling factors, and system prompts.

2.3. Multi-Account IMAP Engine & MailKit Integration
----------------------------------------------------
- `ImapService.cs`:
  * MailKit-powered asynchronous IMAP client (`ImapClient`).
  * Supports SSL/TLS (`SecureSocketOptions.SslOnConnect` and `SecureSocketOptions.Auto`).
  * `TestConnectionAsync()`: Validates credentials and counts unread messages without altering inbox state.
  * `FetchEmailsFromAccountAsync()` & `FetchAllAccountsParallelAsync()`: Concurrently retrieves unread or all messages
    across accounts, downloads MIME structures, extracts clean plaintext from HTML (`ConvertHtmlToPlainText`), strips
    tracking URLs, detects mailing list headers (`List-Unsubscribe`, `List-ID`, `X-Campaign`, etc.), and detects newsletter
    footers (`DetectNewsletterFooter`).
  * Real-time streaming callback (`onEmailFetched`) pushes items into UI progressively during download.
  * Batch triage operations (`DeleteEmailsBatchAsync`, `ArchiveEmailsBatchAsync`) with folder discovery (`Trash`,
    `Archive`, `All Mail`).

2.4. Local & Cloud AI Inference Pipeline
----------------------------------------
- `LlamaServerManager.cs`:
  * Manages embedded local `llama-server.exe` child process for GGUF models.
  * Windows Job Object Integration: Initializes `CreateJobObject` with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (0x2000) and
    assigns the process handle. Guarantees that `llama-server.exe` is instantly killed by the Windows kernel if the parent
    crashes or closes.
  * Server executable resolver: Locates `llama-server.exe` in local directory, WinGet packages directory, or system PATH.
  * Health check probe (`/health`) with polling loop to wait until model is loaded into VRAM.
  * On-demand GPU VRAM freeing (`Stop()`) for instant VRAM unloading.
- `LlmSummarizerService.cs`:
  * Multi-backend OpenAI-compatible REST client for local `llama-server.exe`, local Ollama (`localhost:11434`), and Cloud
    providers (OpenAI, OpenRouter, Groq, DeepSeek).
  * Context Length Management (`PrepareEmailBodyForSummary`): Configurable character limit with clean truncation notes.
  * Newsletter & Marketing Heuristics: Automatic Priority 3 pre-classification notice injection into LLM prompt.
  * Advanced CoT / Reasoning Model Support (`ParseLlmSummaryAndPriority`): Strips `<think>...</think>`, `[THINK]...[/THINK]`,
    and orphaned tags from reasoning models (`DeepSeek-R1`, `QwQ`).
  * Priority parsing (`Priority: 1|2|3`) and clean summary extraction.

2.5. Low-Footprint Win32 System Tray Daemon
-------------------------------------------
- `NativeTrayDaemon.cs`:
  * Headless, pure Win32 message loop utilizing `CreateWindowEx`, `RegisterClassEx`, and `Shell_NotifyIcon`.
  * Zero Windows Forms control overhead; maintains working set memory `< 5 MB RAM`.
  * Mutex: `Global\EmailSummarizer_TrayDaemon_Mutex`.
  * Exit Event: `Global\EmailSummarizer_TrayDaemon_ExitEvent` registered with `ThreadPool.RegisterWaitForSingleObject`.
  * Window Class: `EmailSummarizer_TrayMsgHost_` + GUID.
  * Window Title: `EmailSummarizerTrayHost`.
  * Tray Menu: "📬 Open Email Summarizer", "🔄 Check Emails Now", "🔔 Notifications: Enabled/Disabled", "❌ Exit Tray Daemon".
  * Balloon notifications for newly discovered unread emails.
- `TrayDaemonService.cs`:
  * Background polling service with dynamic refresh timer (1–120 min).
  * Concurrent lightweight envelope checks across enabled accounts.
  * Memory trimming: Periodic `NativeMethods.TrimWorkingSet()` flushes GC generations and process working set.
- `TrayIconHelper.cs`:
  * Extracts embedded resource icon `EmailSummarizer.app.ico`.
  * Dynamically creates 32x32 unread badge icons with high-DPI anti-aliased red indicator.

4.2. Universal Migration Engine (MigrationService.cs)
-----------------------------------------------------
A dedicated service `MigrationService` is introduced in `KerkenezMail.Services` (or `EmailSummarizer.Services` for bridge)
executing on application boot BEFORE normal `ConfigService` initialization:

```csharp
public static class MigrationService
{
    private static readonly string LegacyAppDataFolder = Path.Combine(
        Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
        "EmailSummarizer");

    private static readonly string NewAppDataFolder = Path.Combine(
        Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
        "KerkenezMail");

    private static readonly byte[] LegacyAccountsEntropy = Encoding.UTF8.GetBytes("EmailSummarizer.SecureAccounts.v1");
    private static readonly byte[] LegacySecretsEntropy = Encoding.UTF8.GetBytes("EmailSummarizer.SecureSecrets.v1");

    private static readonly byte[] NewAccountsEntropy = Encoding.UTF8.GetBytes("KerkenezMail.SecureAccounts.v1");
    private static readonly byte[] NewSecretsEntropy = Encoding.UTF8.GetBytes("KerkenezMail.SecureSecrets.v1");

    /// <summary>
    /// Executes atomic migration from EmailSummarizer to KerkenezMail.
    /// Returns MigrationResult with status, log messages, and whether migration occurred.
    /// </summary>
    public static MigrationResult ExecuteMigrationIfNeeded()
    {
        var result = new MigrationResult();

        // 1. Check if legacy AppData exists and new AppData has not been fully established
        bool hasLegacyAppData = Directory.Exists(LegacyAppDataFolder);
        bool hasNewAppData = Directory.Exists(NewAppDataFolder);

        if (hasLegacyAppData)
        {
            MigrateAppData(result);
        }

        // 2. Check and migrate Windows Registry keys
        MigrateRegistryEntries(result);

        // 3. Check and migrate Shortcuts
        MigrateShortcuts(result);

        return result;
    }
}
```

4.3. DPAPI Credential & Secret Re-encryption Architecture
---------------------------------------------------------
The cryptographic migration follows an atomic decrypt-then-re-encrypt flow:

1. Accounts Migration (`accounts.dat`):
   - Step A: Read raw bytes from `%APPDATA%\EmailSummarizer\accounts.dat`.
   - Step B: Decrypt using DPAPI `ProtectedData.Unprotect(rawBytes, LegacyAccountsEntropy, DataProtectionScope.CurrentUser)`.
   - Step C: Deserialize to `List<EmailAccount>` to validate JSON integrity.
   - Step D: Serialize back to JSON and encrypt using new entropy:
     `ProtectedData.Protect(newBytes, NewAccountsEntropy, DataProtectionScope.CurrentUser)`.
   - Step E: Write atomically to `%APPDATA%\KerkenezMail\accounts.dat.tmp` and move to `accounts.dat`.

2. Config & Cloud API Key Migration (`config.json`):
   - Step A: Read text from `%APPDATA%\EmailSummarizer\config.json`.
   - Step B: Parse JSON. If `CloudApiKeyEncrypted` is present:
     * Decrypt Base64 string using `LegacySecretsEntropy`.
     * If decryption succeeds, store plaintext in memory.
     * Re-encrypt plaintext using `NewSecretsEntropy`.
   - Step C: Write updated `AppSettings` JSON to `%APPDATA%\KerkenezMail\config.json`.

4.4. Roaming AppData Atomic Cutover & Verification Protocol
-----------------------------------------------------------
Safety Verification Steps before deleting the legacy folder:
1. Verify `%APPDATA%\KerkenezMail\config.json` exists, is valid JSON, and contains valid settings.
2. If legacy `accounts.dat` existed, verify `%APPDATA%\KerkenezMail\accounts.dat` exists and can be successfully
   decrypted with `NewAccountsEntropy`.
3. If both verifications pass:
   - Perform a clean recursive delete of `%APPDATA%\EmailSummarizer`.
   - Record in `%APPDATA%\KerkenezMail\migration.log`: `[SUCCESS] Legacy AppData migrated and removed cleanly.`
4. If verification fails:
   - Abort deletion of `%APPDATA%\EmailSummarizer`.
   - Log diagnostic error to `%APPDATA%\KerkenezMail\migration_error.log`.
   - Retain legacy data so no user data is ever lost.

4.5. Windows Registry & Run Startup Key Seamless Migration
-----------------------------------------------------------
1. Uninstall Registry Migration:
   - Read existing properties from `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\EmailSummarizer` (InstallDate,
     EstimatedSize, InstallLocation).
   - Create new key `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\KerkenezMail`.
   - Set `DisplayName` = `"Kerkenez Mail"`.
   - Set `UninstallString` = `"\"exePath\" --uninstall"`.
   - Set `QuietUninstallString` = `"\"exePath\" --uninstall --quiet"`.
   - Delete old key `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\EmailSummarizer`.

2. Startup Run Key Migration:
   - Check `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
   - If value `EmailSummarizerTray` or `EmailSummarizer` exists:
     * Create value `KerkenezMailTray` = `"\"exePath\" --daemon"`.
     * Delete values `EmailSummarizerTray` and `EmailSummarizer`.

4.6. Windows Shortcut Relocation & Cleanup Logic
------------------------------------------------
1. Scan for existing legacy shortcuts:
   - `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Email Summarizer.lnk`
   - `%USERPROFILE%\Desktop\Email Summarizer.lnk`
   - `%PUBLIC%\Desktop\Email Summarizer.lnk`
   - `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs\Email Summarizer.lnk`
2. If any legacy shortcut exists:
   - Create corresponding `"Kerkenez Mail.lnk"` pointing to current `exePath` with Description `"Kerkenez Mail - AI Email Assistant"`.
   - Delete all legacy `"Email Summarizer.lnk"` files.

7. EDGE CASES, SAFETY GUARDS & RECOVERY PROTOCOLS
========================================================================================================================

7.1. Partial Migration Failure & Rollback Safeguards
----------------------------------------------------
- Principle of Zero Data Loss: Under no circumstances should legacy files be deleted unless the new files have been
  written, verified by file size, and successfully test-decrypted in the same process.
- If DPAPI decryption of `accounts.dat` fails due to user profile corruption, the original `accounts.dat` is preserved in
  `%APPDATA%\EmailSummarizer` and copied as-is to `%APPDATA%\KerkenezMail\accounts.dat.bak`.

7.2. Multi-Instance & Daemon Concurrency Collision Handling
-----------------------------------------------------------
- When `v0.5.0-bridge` or `v1.0.0` launches, an active background daemon from an older version might still be running in
  memory with the old mutex `Global\EmailSummarizer_TrayDaemon_Mutex`.
- Migration step:
  1. Signal the old exit event: `EventWaitHandle.OpenExisting(@"Global\EmailSummarizer_TrayDaemon_ExitEvent").Set()`.
  2. Wait up to 1000ms for graceful daemon termination.
  3. If old daemon was running as a process named `EmailSummarizer`, terminate cleanly.
  4. Acquire new mutex `Global\KerkenezMail_TrayDaemon_Mutex` and start the modernized daemon.

7.3. Permission Elevation & Access Denied Mitigation
----------------------------------------------------
- All registry writes target `HKEY_CURRENT_USER` (HKCU). This guarantees zero UAC elevation prompts for normal users.
- Shortcut creation in `%APPDATA%\Microsoft\Windows\Start Menu\Programs` and `%USERPROFILE%\Desktop` requires no admin rights.

7.4. Corrupt Legacy Config Auto-Healing
---------------------------------------
- If legacy `config.json` is missing or corrupted, `ConfigService.HealAndNormalizeSettings()` generates clean default
  settings while preserving any salvageable `AccountIds` and model paths.
